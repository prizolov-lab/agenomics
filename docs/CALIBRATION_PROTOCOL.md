# Протокол калибровки весов и порогов

Статус: черновик, заранее зафиксированные правила. Менять их после того, как
данные посмотрены, нельзя; изменение протокола оформляется отдельной записью.

## 1. Зачем и когда

Веса осей и пороги Trust Score сейчас заданы экспертно (модель 0.9.6). Их можно
менять только на реальных данных и только по этому протоколу. До выполнения
условий раздела 2 формула остаётся замороженной, а проверка «предсказывает ли
score исходы» идёт по `VALIDATION_PROTOCOL.md`.

## 2. Условия допуска (все сразу)

- Источники данных только реальные: ядро Prizolov Agent OS, Ночной аналитик,
  prizolov-sports-ai. Когорты Framework Evaluation и stress_* для подгонки весов
  не используются: условия там заданы экспериментом, а не жизнью.
- Не меньше 100 событий на цель (runtime_failure, task_failure) и не меньше 30
  событий каждого класса в выборке калибровки.
- Не меньше 3 независимых агентов или конфигураций с разным Trust Score; не
  меньше 50 исходов Q4 по цели, на которой калибруем.
- Независимых единиц считается по задачам/матчам, а не по строкам: повторные
  оценки одного события (горизонты, несколько агентов на одном матче) не
  увеличивают объём.

## 3. Разбиение (хронологическое, один раз)

1. Все допущенные данные упорядочиваются по времени заморозки предсказания.
2. Первые 60% это выборка калибровки, последние 40% это проверочная выборка.
3. Проверочная выборка не используется ни для подбора, ни для выбора между
   вариантами, ни для остановки. Её смотрят один раз, после фиксации результата
   калибровки.

## 4. Что можно калибровать (по возрастанию риска)

1. **Перевод score в вероятность** (Platt или изотоническая регрессия). Не
   меняет порядок агентов, поэтому не влияет на AUC; влияет на Brier и ECE.
2. **Пороги меток** (Trusted / Conditional / High Risk) по ожидаемой частоте
   исходов. Нужно не меньше 30 событий в каждой группе.
3. **Веса осей**, только при 200+ событиях на цель. Ограничения: веса
   неотрицательны, сумма равна 1, отклонение от экспертных весов не больше
   0,15 по оси, регуляризация. Число перепробованных вариантов записывается и
   учитывается как число проверенных гипотез.

## 5. Критерий принятия

Кандидат принимается, только если на проверочной выборке одновременно:
- ROC-AUC выше, чем у модели 0.9.6, и 95% интервал разности (bootstrap по
  агентам) не включает ноль;
- не хуже baseline «история агента» и baseline «частота условия», либо
  обоснованно лучше при независимом наборе агентов (leave-one-agent-out);
- калибровка (Brier, ECE) не хуже 0.9.6.

Если условия не выполнены, результат фиксируется как «калибровка не улучшила
модель», формула остаётся 0.9.6. Это допустимый и полноценный итог.

## 6. Версионирование

Принятый кандидат получает новый номер модели (например, 0.10.0) и запускается
в «тени» рядом с 0.9.6 (champion/challenger) не меньше одного цикла накопления.
0.9.6 не перезаписывается, обе версии сравниваются на одинаковых задачах.
Переход на новую модель решает владелец.

## 7. Что нельзя утверждать

До прохождения проверочной выборки нельзя писать, что «веса откалиброваны на
реальных данных». Допустимая формулировка: «калибровка проведена по протоколу,
результат на независимой проверочной выборке: ...» с интервалами.
